# Plain-language rewrite

This skill edits communication. It does not authorise implementation, publication, extra tasks, or tool use unrelated to the rewrite.

1. Identify the result, relevant facts, uncertainty, and any real decision for the reader.
2. Put that result or decision first. Use ordinary words and short paragraphs.
3. Preserve technical identifiers, errors, paths, conditions, and requirement strength. Never change “may” to “will” merely to sound more direct.
4. Use Markdown only where it helps: a short heading, a few bullets, numbered actions, or a copyable command.
5. Remove repeated context, filler, unnecessary acronyms, and unrelated advice. Do not add fake progress, time estimates, or a compulsory next step.
6. Return the revised text. Add a brief qualification only when the original meaning is ambiguous or a factual gap prevents a safe rewrite.

Do not assume the reader has a diagnosis. Simplify the wording, not the underlying technical decision.
